01

실습 꾸러미와 작업 폴더 준비

할 일

  1. 위의 실습 꾸러미 ZIP을 내려받습니다. ZIP은 여러 파일을 담은 포장 상자입니다. 압축을 풀어야 파일을 바꿀 수 있어요.
  2. 문서에 practice-과정이름 폴더를 만들고 압축을 푼 파일들을 넣습니다. START-HERE.txt가 바로 보이는 위치를 찾으세요.
  3. Codex에서 그 폴더를 프로젝트로 열고 새 작업을 만듭니다. 01 과정의 폴더 열기 단계가 낯설면 먼저 돌아가 연습하세요.
  4. 아래 요청을 보내 파일 목록을 확인합니다. 이번에는 파일을 수정하지 않습니다.

Windows에서

ZIP에서 마우스 오른쪽 버튼 → 모두 압축 풀기. 풀린 폴더를 문서로 복사하세요. 파일 탐색기에서 START-HERE.txt가 있는지 확인합니다. ZIP 안을 바로 열어 작업하지 마세요.

Mac에서

Finder의 다운로드에서 ZIP을 두 번 누르면 폴더가 생깁니다. 그 폴더를 문서로 옮기세요. Finder에서 START-HERE.txt가 있는지 확인합니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
지금 열린 연습 폴더의 경로와 파일 목록만 알려줘. 아직 파일을 수정하지 마.
확인할 파일: sources/01-rules.txt, sources/02-check.txt, sources/03-request.txt, updates/04-rules-v2.txt
정상 결과

Codex가 알려준 경로가 내가 고른 폴더와 같고, sources/01-rules.txt, sources/02-check.txt, sources/03-request.txt, updates/04-rules-v2.txt가 보입니다.

막혔을 때 ＋

파일이 없으면 압축을 푼 바깥 폴더가 아니라 START-HERE.txt가 있는 폴더를 다시 여세요. 파일명 끝에 (1)이 있으면 실제 이름을 요청문에 적습니다.

02

원문과 내 생각을 나눠요

할 일

  1. sources 안의 원문 세 개를 직접 읽습니다. updates는 아직 사용하지 않습니다.
  2. 이 실습 자료는 실제 모임 규칙이 아닌 교육용 가상 문서입니다.
  3. 원문은 그대로, 요약은 notes, 전체 길잡이는 index.md로 구분합니다. 확인 날짜는 내가 실제 읽은 날짜를 기록하세요.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
sources의 원문 3개만 목록으로 정리해 source-register.md를 만들어줘.
각 항목에 자료 ID(S1~S3), 파일 경로, 문서 제목, 작성자, 문서에 적힌 날짜를 써줘.
내 확인일은 [직접 입력]으로 남겨줘. notes 폴더를 준비하고 원문은 수정하지 마.
updates와 expected는 아직 읽지 마.
정상 결과

S1=운영 규칙, S2=결과 확인, S3=요청문 구성입니다. 문서 날짜와 내가 확인한 날이 서로 다른 칸입니다.

막혔을 때 ＋

자료에 없는 공개 URL을 만들지 않습니다. 가상 자료는 로컬 경로가 출처입니다.

03

자료 하나를 짧은 노트로 바꿔요

할 일

  1. 먼저 S1만 요약합니다. 모든 자료를 한 번에 섞지 마세요.
  2. 요약마다 근거 항목을 적고 내 해석은 별도 칸으로 둡니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
sources/01-rules.txt를 읽고 notes/rules.md를 만들어줘.
형식: 핵심 사실 3개 / 내 해석(아직 없음) / 모르는 점 / 원문 링크.
사실마다 S1의 항목 번호를 붙여줘. 원문 링크는 ../sources/01-rules.txt야.
모임 장소나 회비는 추측하지 마. sources는 수정하지 마.
정상 결과

파일 이름 규칙 result.txt에 S1-2 근거가 붙습니다. 장소·회비는 미정. 원문 링크가 정확합니다.

막혔을 때 ＋

내 해석에 AI 의견이 들어가면 “내 해석은 아직 없음으로 되돌려줘”라고 요청하세요.

04

노트와 목차를 연결해요

할 일

  1. S2·S3도 각각 notes/check.md, notes/request.md로 만듭니다.
  2. index.md에서 세 노트로, 각 노트에서 원문과 관련 노트로 이동하도록 연결합니다.
  3. Codex의 Markdown 미리보기에서 링크를 누르세요. 텍스트로만 열리면 괄호 속 경로와 실제 파일을 대조해 열어도 됩니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
S2는 notes/check.md, S3는 notes/request.md로 같은 형식의 노트를 만들어줘.
notes/rules.md와 함께 세 노트의 제목·한 줄 설명·상대 경로 링크를 index.md에 넣어줘.
check와 request 노트는 서로 관련 노트로 연결해줘. 각 노트에는 원문으로 돌아가는 링크를 남겨줘.
링크 대상 파일이 실제 존재하는지 확인해줘.
정상 결과

index.md → notes/check.md → ../sources/02-check.txt 순서로 원문을 찾을 수 있습니다. 관련 노트 연결도 있습니다.

막혔을 때 ＋

파일 이름 대소문자와 ../를 확인합니다. 루트 index.md는 notes/…, notes 안에서는 ../sources/…입니다.

05

근거가 있는 답을 요청해요

할 일

  1. 정답이 있는 질문과 없는 질문을 함께 묻습니다.
  2. 답을 읽고 실제 원문 항목을 열어 확인합니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
sources와 notes만 근거로 output/answers-before.md를 만들어줘.
질문 1: 결과 파일 이름은 무엇인가요?
질문 2: 결과를 확인하는 방법은?
질문 3: 모임 회비는 얼마인가요?
답마다 근거 파일 경로와 항목 번호를 써줘. 자료에 없으면 자료에 없음이라고 적어줘.
외부 검색과 updates 참조는 하지 마.
정상 결과

파일 이름=result.txt(S1-2), 파일 직접 열기(S2-1), 회비=자료에 없음(S1-3에서 미정)입니다.

막혔을 때 ＋

회비를 계산하거나 권장 금액을 제시하면 “내 질문은 추천이 아니라 자료 확인이야”라고 수정하세요.

06

새 자료를 추가하고 충돌을 찾아요

할 일

  1. updates/04-rules-v2.txt를 sources로 복사합니다. 기존 S1은 지우지 않습니다.
  2. S4가 단순히 최근 문서인지, 이전 규칙을 바꾼다고 명시했는지 읽습니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
updates/04-rules-v2.txt를 sources/04-rules-v2.txt로 복사해줘. 같은 파일이 있으면 먼저 알려줘.
S1과 S4를 비교해 output/conflicts.md에 이전 규칙/새 규칙/대체 근거를 적어줘.
아직 notes/rules.md는 고치지 마. 날짜가 최근이라는 이유만으로 자동 선택하지 마.
정상 결과

S4-1은 S1의 result.txt 규칙을 번호 붙인 이름으로 교체한다고 명시합니다. 가상 자료 사용 조건은 그대로입니다.

막혔을 때 ＋

대체 여부가 불명확한 실제 자료라면 충돌로 남기고 작성자에게 확인해야 합니다. 이번 샘플에는 명시된 문장이 있습니다.

07

현재 규칙과 변경 기록을 남겨요

할 일

  1. 무엇이 바뀌는지 확인한 뒤 노트 갱신을 요청합니다.
  2. 기존 원문은 지우지 않고 현재 규칙과 과거 규칙을 노트에서 구분합니다.
  3. 질문을 다시 해 갱신 결과를 확인하세요.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
S4의 명시된 변경을 반영해 notes/rules.md의 현재 이름 규칙을 갱신해줘.
이전 규칙과 S1 출처를 과거 규칙 영역에 남기고, 현재 규칙에는 S4-1 링크를 붙여줘.
source-register.md와 index.md를 갱신하고 changes.md에 변경 이유를 남겨줘.
같은 질문 3개에 다시 답한 output/answers-after.md도 만들어줘. 기존 답변은 보존해줘.
정상 결과

현재 파일 이름은 result-01.txt, result-02.txt 방식이며 S4 근거가 있습니다. 회비는 여전히 미정입니다. expected/answer-after.md로 비교하세요.

막혔을 때 ＋

답이 옛날 규칙이면 “현재 규칙 영역과 변경 근거를 다시 읽어줘”라고 합니다. 원문을 새 내용으로 덮어쓰면 복사본에서 원문을 복구하세요.

08

내 자료 하나로 혼자 반복해요

할 일

  1. 공개 가능한 짧은 글을 직접 쓰거나 사용 권한이 있는 자료 하나를 고릅니다.
  2. sources/05-my-note.txt로 저장합니다. 텍스트 편집이 어렵다면 Codex에게 내 문장을 그대로 저장해달라고 요청하세요.
  3. 새 작업에서 수집→요약→연결→질문 확인을 반복합니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
sources/05-my-note.txt를 새 자료로 등록하고 별도 노트·원문 링크·index.md 항목을 추가해줘.
기존 자료와 충돌하면 output/my-conflicts.md에 표시하고 임의로 합치지 마.
새 자료만으로 답할 수 있는 질문 하나와 답할 수 없는 질문 하나를 만들고 근거를 달아줘.
원문을 바꾸지 마.
정상 결과

내 자료가 목차에 추가되고 관련 원문으로 돌아갈 수 있습니다. 자료에 없는 답은 없다고 말합니다.

막혔을 때 ＋

실제 개인정보가 포함되어 있으면 연습 파일에 옮기기 전에 가상의 내용으로 바꿉니다. PDF가 복잡하면 이번에는 짧은 텍스트부터 시작하세요.

내 힘으로 할 수 있나요?

  1. 회비가 얼마인지 물었을 때 추측을 멈추나요?
  2. S1과 S4의 차이와 현재 규칙의 근거를 설명하나요?
  3. 요약에서 원문으로 돌아갈 수 있나요?
