첫 화면은 한 가지를 말해요

누가 읽고 무엇을 알면 되는지 정합니다. 제목과 다음 행동 하나가 방문자를 돕습니다. 없는 경력이나 성과를 채우지 않습니다.

방문자: 모임원 / 알릴 것: 학습 주제 / 행동: 작업 보기

버튼이 많으면 좋은 페이지일까요?

목적에 맞는 행동이 명확한지가 중요합니다.

좁은 화면에서도 읽혀야 해요

작은 화면에서는 한 열로 배치합니다. 제목·본문·버튼을 실제 너비에서 확인합니다. 창이 작아 보인다는 느낌만으로 확인을 마치지 않습니다.

1440px: 나란히 / 768px: 여유 있게 / 390px: 한 열

휴대폰에서 옆으로 밀어야 글이 보인다면요?

가로 넘침입니다. 긴 문장과 고정 너비를 확인합니다.

만들기·수정·복원은 한 세트예요

작동하는 파일을 백업하고 한 번에 한 부분을 고칩니다. 수정 후 실제 브라우저를 새로고침합니다. 내 컴퓨터의 파일과 인터넷 공개 사이트는 다릅니다.

백업 → 한 줄 변경 → 새로고침 → 이전 파일 비교

01

실습 꾸러미와 작업 폴더 준비

할 일

  1. 위의 실습 꾸러미 ZIP을 내려받습니다. ZIP은 여러 파일을 담은 포장 상자입니다. 압축을 풀어야 파일을 바꿀 수 있어요.
  2. 문서에 practice-과정이름 폴더를 만들고 압축을 푼 파일들을 넣습니다. START-HERE.txt가 바로 보이는 위치를 찾으세요.
  3. Codex에서 그 폴더를 프로젝트로 열고 새 작업을 만듭니다. 01 과정의 폴더 열기 단계가 낯설면 먼저 돌아가 연습하세요.
  4. 아래 요청을 보내 파일 목록을 확인합니다. 이번에는 파일을 수정하지 않습니다.

Windows에서

ZIP에서 마우스 오른쪽 버튼 → 모두 압축 풀기. 풀린 폴더를 문서로 복사하세요. 파일 탐색기에서 START-HERE.txt가 있는지 확인합니다. ZIP 안을 바로 열어 작업하지 마세요.

Mac에서

Finder의 다운로드에서 ZIP을 두 번 누르면 폴더가 생깁니다. 그 폴더를 문서로 옮기세요. Finder에서 START-HERE.txt가 있는지 확인합니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
지금 열린 연습 폴더의 경로와 파일 목록만 알려줘. 아직 파일을 수정하지 마.
확인할 파일: profile.txt, revision.txt
정상 결과

Codex가 알려준 경로가 내가 고른 폴더와 같고, profile.txt, revision.txt가 보입니다.

막혔을 때 ＋

파일이 없으면 압축을 푼 바깥 폴더가 아니라 START-HERE.txt가 있는 폴더를 다시 여세요. 파일명 끝에 (1)이 있으면 실제 이름을 요청문에 적습니다.

02

누구에게 무엇을 보여줄지 정해요

할 일

  1. profile.txt의 가상 소개 내용을 읽습니다.
  2. 방문자·목적·버튼 동작을 각각 한 문장으로 확인합니다.
  3. 완성 예시는 위 링크로 먼저 볼 수 있지만, 처음에는 직접 만들고 나중에 비교해보세요.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
profile.txt를 읽고 한 페이지 구성안을 설명해줘.
순서는 소개 → 관심사 3개 → 첫 작업 → 같은 페이지 안 이동 버튼이야.
제공되지 않은 연락처·경력·가격·후기·외부 주소는 만들지 마.
코드 작성 전에 각 영역에서 보여줄 문장과 버튼의 목적만 알려줘.
정상 결과

방문자는 모임원, 목적은 관심사와 첫 작업 소개입니다. 버튼은 같은 페이지 작업 영역으로 갑니다.

막혔을 때 ＋

신청·결제·로그인을 제안하면 “이번 목표는 소개 한 페이지야. 그 기능은 빼줘”라고 범위를 줄이세요.

03

내 첫 페이지를 만들어달라고 해요

할 일

  1. Codex가 제안한 문구를 읽고 아래 제작 요청을 보냅니다.
  2. 이번에는 설치 없이 브라우저에서 열 수 있는 단일 HTML 파일로 만듭니다.
  3. 외부 이미지와 글꼴 없이도 완성할 수 있습니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
profile.txt에 있는 내용만 사용해 output/index.html을 만들어줘.
CSS를 HTML 안에 넣은 한 파일로 만들고, 외부 라이브러리·이미지·글꼴 요청은 넣지 마.
흰색과 짙은 남색을 기본으로, 네온 라임을 버튼과 강조에만 사용해줘. 밝은 배경 글자는 어둡게.
소개, 관심사 3개, 첫 작업 소개(id=work)를 넣어줘. 버튼은 href="#work"로 이동하게 해줘.
390px에서는 한 열, PC에서는 여백 있는 카드로. 키보드 초점이 보여야 해.
기존 파일이 있으면 덮어쓰기 전에 알려줘. 인터넷에 올리지 마.
정상 결과

output/index.html 파일이 있습니다. 브라우저로 열 수 있는 한 페이지이고 입력 파일은 그대로입니다.

막혔을 때 ＋

도구 설치를 계속 요구하면 “현재 요청은 단일 HTML이야. 추가 설치 없이 만들 수 있는 범위로 해줘”라고 말하세요.

04

파일을 실제 브라우저로 열어요

할 일

  1. 파일 탐색기/Finder에서 output/index.html을 찾습니다.
  2. 마우스 오른쪽 버튼의 연결 프로그램/다음으로 열기에서 웹 브라우저를 고릅니다.
  3. 코드가 아니라 화면이 보이는지, 제목·관심사·첫 작업 문구가 맞는지 확인합니다.

Windows에서

파일 탐색기에서 output 폴더 → index.html 오른쪽 클릭 → 연결 프로그램 → Edge 또는 Chrome을 고릅니다. 파일 확장명을 표시하면 .html인지 확인하기 쉽습니다.

Mac에서

Finder에서 output/index.html 오른쪽 클릭 → 다음으로 열기 → Safari 또는 Chrome을 선택합니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
output/index.html을 내가 볼 수 있도록 브라우저로 열어줘.
열 수 없으면 파일의 실제 위치와 수동으로 여는 방법을 알려줘.
화면을 열었다는 말과 실제 화면 표시를 구분해서 알려줘.
정상 결과

주소가 file:로 시작할 수 있습니다. 이것은 내 컴퓨터 파일을 보는 상태이며 인터넷 공개가 아닙니다.

막혔을 때 ＋

글자 코드가 보이면 텍스트 편집기로 연 것입니다. 브라우저로 다시 열고, index.html.txt처럼 이중 확장자가 아닌지도 확인하세요.

05

버튼을 누르고 Tab으로 이동해요

할 일

  1. “나의 첫 작업 보기”를 눌러 작업 소개로 이동하는지 확인합니다.
  2. 키보드 Tab을 눌러 버튼의 테두리나 표시가 보이는지 봅니다. Enter로도 눌러봅니다.
  3. 안 되는 동작은 실제 행동→기대한 결과→현재 결과 순서로 설명합니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
확인할 동작: 첫 작업 보기 버튼을 누르면 #work로 이동해야 해.
Tab으로 버튼에 도달하고 Enter로 실행되어야 하며 초점 표시가 보여야 해.
현재 HTML의 링크와 id를 확인해서 필요한 부분만 고쳐줘. 문구와 다른 영역은 유지해줘.
정상 결과

마우스와 키보드 모두 작업 영역으로 이동합니다. 버튼이 장식이 아니라 실제 링크입니다.

막혔을 때 ＋

같은 화면의 위쪽에서 이동 변화가 작으면 주소 끝의 #work와 작업 제목 위치를 보세요. 잘못된 id면 버튼과 영역 이름을 맞춥니다.

06

휴대폰 너비에서 읽어봐요

할 일

  1. Chrome/Edge의 개발자 도구를 열고 기기 모양 버튼으로 반응형 화면을 켭니다. 아래 운영체제 단축키를 사용하세요.
  2. 너비 390을 입력하고 소개·카드·버튼을 확인합니다. 태블릿은 768, PC는 1440으로 비교합니다.
  3. 작은 화면 검사 후 기기 모드를 끄고 개발자 도구를 닫습니다. 이 과정은 실제 휴대폰 전송 없이 화면 폭을 흉내 내는 검사입니다.

Windows에서

Chrome/Edge에서 Ctrl+Shift+I로 개발자 도구 → Ctrl+Shift+M으로 기기 도구를 켭니다. 반응형/Responsive에서 너비 390을 입력하세요.

Mac에서

Chrome/Edge에서 ⌘+Option+I → ⌘+Shift+M으로 기기 도구를 켭니다. Safari에서는 메뉴가 다르므로 이 실습은 Chrome/Edge를 기준으로 따라갑니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
390px에서 한 열로 배치되고 긴 글도 화면 밖으로 나가지 않게 점검해줘.
버튼 터치 영역은 충분히 크게, 본문은 읽기 쉬운 크기로 유지해줘.
768px와 1440px에서도 내용이 가려지지 않게 해줘. 수정 전 output/index.html을 backup/index-before-mobile.html로 복사해줘.
정상 결과

390px에서 가로 스크롤 없이 카드와 버튼이 보입니다. 네온 라임 위의 글자는 어둡고 읽을 수 있습니다.

막혔을 때 ＋

개발자 도구가 낯설면 진행자와 함께 너비 입력 칸을 찾으세요. 창을 줄이는 것은 보조 확인이고, 390px 확인 완료와 같다고 적지 않습니다.

07

한 줄만 바꾸고 다시 열어요

할 일

  1. revision.txt의 새 소개 문장을 읽습니다.
  2. 변경 전에 백업 파일을 남기고, 정확히 한 줄만 바꾸도록 요청하세요.
  3. 브라우저를 새로고침해 새 문장이 보이는지 확인합니다.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
output/index.html을 backup/index-before-copy.html로 복사해줘. 같은 백업이 있으면 새 이름을 써줘.
revision.txt의 문장으로 한 줄 소개만 바꿔줘.
관심사·이름·링크·스타일은 그대로 유지하고 바뀐 문장을 보여줘.
정상 결과

“작은 자동화를 함께 배우는 사람입니다.”가 보이고 다른 문구와 버튼 동작이 유지됩니다.

막혔을 때 ＋

바뀌지 않으면 편집한 파일과 브라우저에 열린 파일의 경로를 비교하세요. 다른 복사본을 보고 있을 수 있습니다.

08

백업을 다른 이름으로 복원해요

할 일

  1. 실수해도 돌아갈 수 있다는 것을 연습합니다.
  2. 현재 결과를 덮어쓰지 않고 백업을 별도 파일로 복원합니다.
  3. 두 파일을 번갈아 열어 이전 문구와 바뀐 문구를 비교하세요.

입력 예시

입력 예시 · 실행할 앱을 확인하세요
backup/index-before-copy.html을 output/restored.html로 복사해줘.
현재 output/index.html은 유지해줘. 두 파일의 소개 문구 차이를 알려줘.
정상 결과

restored.html에는 이전 소개 문구가, index.html에는 새 소개 문구가 있습니다.

막혔을 때 ＋
