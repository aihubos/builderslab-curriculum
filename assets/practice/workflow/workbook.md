# 두 주의 메모로 만드는 나의 업무 루틴

같은 규칙으로 보고서 두 개와 비교표를 만들고, 다시 쓰는 요청문을 남깁니다.

## 먼저 확인

01에서 입력 파일을 읽고 결과 파일을 직접 확인해봤다면 시작할 수 있어요.

## 준비

ZIP 압축을 풀고 START-HERE.txt가 보이는 폴더를 작업 폴더로 엽니다. AI 작업은 본인 앱에서 실행합니다.

## 01. 실습 꾸러미와 작업 폴더 준비

### 할 일

1. 위의 실습 꾸러미 ZIP을 내려받습니다. ZIP은 여러 파일을 담은 포장 상자입니다. 압축을 풀어야 파일을 바꿀 수 있어요.

2. 문서에 practice-과정이름 폴더를 만들고 압축을 푼 파일들을 넣습니다. START-HERE.txt가 바로 보이는 위치를 찾으세요.

3. Codex에서 그 폴더를 프로젝트로 열고 새 작업을 만듭니다. 01 과정의 폴더 열기 단계가 낯설면 먼저 돌아가 연습하세요.

4. 아래 요청을 보내 파일 목록을 확인합니다. 이번에는 파일을 수정하지 않습니다.

### Windows

ZIP에서 마우스 오른쪽 버튼 → 모두 압축 풀기. 풀린 폴더를 문서로 복사하세요. 파일 탐색기에서 START-HERE.txt가 있는지 확인합니다. ZIP 안을 바로 열어 작업하지 마세요.

### Mac

Finder의 다운로드에서 ZIP을 두 번 누르면 폴더가 생깁니다. 그 폴더를 문서로 옮기세요. Finder에서 START-HERE.txt가 있는지 확인합니다.

### 입력 예시

```text

지금 열린 연습 폴더의 경로와 파일 목록만 알려줘. 아직 파일을 수정하지 마.
확인할 파일: input/week-01.txt, input/week-02.txt, input/options.txt, templates/report-template.md

```

### 정상 결과

Codex가 알려준 경로가 내가 고른 폴더와 같고, input/week-01.txt, input/week-02.txt, input/options.txt, templates/report-template.md가 보입니다.

### 막혔을 때

파일이 없으면 압축을 푼 바깥 폴더가 아니라 START-HERE.txt가 있는 폴더를 다시 여세요. 파일명 끝에 (1)이 있으면 실제 이름을 요청문에 적습니다.

- [ ] 연습 폴더와 입력 파일을 확인했어요

## 02. 맡길 일을 네 문장으로 정해요

### 할 일

1. 업무 전체가 아니라 주간 메모 정리 하나를 고릅니다.

2. 아래 상황·할 일·목적·조건을 읽고 내가 맡기는 일을 한 문장으로 설명해보세요.

3. Codex가 제안한 순서를 읽습니다. 아직 보고서를 만들지 않습니다.

### 입력 예시

```text

상황: 나는 모임 메모를 매주 보고서로 정리하는 초보자야.
할 일: input/week-01.txt를 templates/report-template.md 형식으로 정리하려고 해.
목적: 누가 무엇을 해야 하는지 다시 확인하고 싶어.
조건: 원문에 없는 정보는 미정, 원문 보존, output 폴더에 새 결과만 저장.
먼저 입력·작업·결과와 확인할 기준을 짧게 설명해줘. 아직 실행하지 마.

```

### 정상 결과

입력=1주차 메모, 작업=항목 분류, 결과=주간 보고로 구분합니다. 빈 정보는 추측하지 않는다는 조건이 들어갑니다.

### 막혔을 때

계획이 너무 길면 “설치나 추가 도구 없이 파일 정리 3단계로 줄여줘”라고 요청하세요.

- [ ] 입력·작업·결과를 설명할 수 있어요

## 03. 첫 보고서를 만들어요

### 할 일

1. 아래 요청을 복사해 Codex에 보냅니다.

2. 완료 답변을 받은 뒤 output 폴더를 열고 week-01.md를 직접 확인하세요. .md는 제목과 표 표시를 붙인 텍스트입니다.

3. Codex의 파일 미리보기로 열거나 텍스트 편집기로 읽을 수 있습니다.

### 입력 예시

```text

input/week-01.txt만 읽고 templates/report-template.md 형식의 output/week-01.md를 만들어줘.
원문에 없는 정보는 미정으로 쓰고 요일을 임의의 날짜로 바꾸지 마.
완료한 일과 다음 할 일을 구분해줘. 입력·템플릿·expected는 수정하지 마.
output 폴더가 없으면 만들어줘. 같은 이름이 있으면 덮어쓰지 말고 알려줘.
완료 후 실제 저장 경로를 알려줘.

```

### 정상 결과

완료: 민지의 소개 초안, 준호의 자료 2개. 다음 일: 민지의 그림/미정, 준호의 나머지 1개/금요일, 안내문/담당자 미정. 날짜·장소는 미정입니다.

### 막혔을 때

대화에 표만 있으면 “지금 결과를 output/week-01.md로 저장해줘”라고 요청하세요. 이름이 다른 파일이면 이후에도 그 실제 이름을 사용합니다.

- [ ] 저장된 첫 보고서를 열었어요

## 04. 일부러 틀린 보고서를 고쳐봐요

### 할 일

1. input/week-01.txt와 expected/fix-me.md를 나란히 읽습니다.

2. AI에게 묻기 전에 틀린 내용 3개를 직접 말해봅니다.

3. 수정 요청 후 expected/week-01.md도 열어 실제 첫 결과와 비교하세요. 정답 예시는 문장 모양보다 정보 비교용입니다.

### 입력 예시

```text

expected/fix-me.md를 input/week-01.txt와 비교해줘.
틀린 주장, 원문의 근거, 고친 표현을 표로 만들어 output/corrections.md에 저장해줘.
정답 비교 파일과 원문은 수정하지 마.

```

### 정상 결과

① 자료는 3개 모두가 아니라 2개 완료 ② 안내문 담당자·마감일은 미정 ③ 모임 날짜도 미정입니다.

### 막혔을 때

AI가 “모두 맞다”고 하면 원문에서 대응하는 문장을 인용해 달라고 요청하세요. 요약을 또 요약하지 말고 원문으로 돌아갑니다.

- [ ] 틀린 내용 세 가지와 근거를 찾았어요

## 05. 서로 다른 자료를 비교표로 만들어요

### 할 일

1. input/options.txt를 엽니다. A와 B는 가상의 모임 방식입니다.

2. 동일한 항목으로 표를 만들고 없는 정보는 비워두지 말고 미정으로 표시합니다.

### 입력 예시

```text

input/options.txt만 읽고 장소·다시보기·질문 방식·준비물·가격·일정·정원을 행으로 하는 A/B 비교표를 output/options.md에 만들어줘.
정보가 없으면 미정. 어떤 방식이 더 저렴한지는 판단하지 마. 원문을 보존해줘.

```

### 정상 결과

A는 온라인·다시보기 가능·게시판 질문, B는 오프라인·다시보기 없음·현장 질문입니다. 가격·일정·정원은 두 방식 모두 미정입니다.

### 막혔을 때

표에 새로운 가격이나 장점이 생기면 “자료에 없는 항목을 삭제하고 근거 파일 이름을 붙여줘”라고 요청하세요.

- [ ] 같은 항목으로 비교한 표를 확인했어요

## 06. 좋은 요청문을 파일로 남겨요

### 할 일

1. 한 번 잘 된 요청을 다음에도 쓰도록 templates/request.txt로 남깁니다.

2. 입력과 출력 이름을 바꿀 자리만 대괄호로 표시합니다.

3. 사람이 읽는 안내와 자동으로 적용되는 규칙은 다릅니다. 이 단계의 파일은 매번 읽으라고 지정해야 합니다.

### 입력 예시

```text

지금 성공한 보고서 작성 규칙을 templates/request.txt에 정리해줘.
입력 파일은 [입력파일], 출력은 [출력파일]로 표시해줘.
형식은 templates/report-template.md를 따르고, 원문 보존·미정 처리·요일 보존·기존 결과 덮어쓰기 금지를 포함해줘.
이 파일은 자동 실행 프로그램이 아니라 내가 다시 읽히는 요청문이야.

```

### 정상 결과

두 대괄호 자리와 보고서 형식, 원문 보존 규칙이 있습니다. 정리한 요청문을 텍스트로 다시 열 수 있습니다.

### 막혔을 때

특정 사람 이름이 고정되어 있으면 “사람과 날짜를 예시로 박아 넣지 말고 이번 입력에서 읽게 해줘”라고 수정하세요.

- [ ] 재사용 요청문을 저장했어요

## 07. 두 번째 자료에도 같은 규칙을 써요

### 할 일

1. Codex의 같은 폴더에서 새 작업을 엽니다.

2. 아래 요청을 보낸 뒤 2주차 결과와 expected/week-02.md를 비교합니다.

3. 1주차 결과도 다시 열어 그대로 남았는지 확인하세요.

### 입력 예시

```text

templates/request.txt의 규칙을 읽고 실행해줘.
[입력파일]은 input/week-02.txt, [출력파일]은 output/week-02.md야.
이번 입력만 사용하고 week-01.md는 그대로 남겨줘.
끝나면 두 결과의 담당자·할 일 차이를 설명해줘.

```

### 정상 결과

수진은 후보 2개 정리 완료, 비교표는 다음 일입니다. 도윤은 설치 안내 작성 중/수요일입니다. 안내문 담당자는 미정. 민지·준호가 등장하면 이전 입력이 섞였는지 확인합니다.

### 막혔을 때

“앞에서 했던 대로”만 쓰지 말고 규칙 파일 이름과 이번 입력 이름을 모두 적으세요.

- [ ] 두 번째 보고서도 같은 규칙으로 만들었어요

## 08. 프로젝트 규칙과 스킬을 구분해요

### 할 일

1. 프로젝트 규칙은 이 폴더에서 항상 지킬 약속이고, 스킬은 특정 일을 반복하는 절차입니다.

2. 이번에는 프로젝트에만 적용할 AGENTS.md를 만들고 새 작업에서 읽히는지 확인합니다.

3. 스킬 확장은 아래 추가 실습에서 이어갑니다. 다른 프로젝트나 사용자 전체 설정은 바꾸지 않습니다.

### 입력 예시

```text

현재 연습 폴더에 AGENTS.md가 없으면 만들어줘. 이미 있으면 덮어쓰지 말고 내용을 먼저 보여줘.
규칙: 원문과 expected 보존, 이번 입력만 사용, 없는 정보는 미정, output에 새 파일 저장, 외부 발송·예약 생성·멀티에이전트 사용 금지.
사용자 전체 설정은 바꾸지 마.
저장 후 새 작업에서 확인할 질문도 알려줘.

```

### 정상 결과

폴더의 AGENTS.md가 보입니다. 새 작업에서 “이번 프로젝트에서 읽은 규칙과 그 파일 위치를 알려줘”라고 했을 때 해당 파일과 규칙이 확인됩니다.

### 막혔을 때

읽지 못하면 현재 작업 폴더가 맞는지 확인하고 새 작업을 열어보세요. 해결 전에는 요청문에 규칙 파일을 직접 읽으라고 적습니다.

- [ ] 프로젝트 규칙이 적용되는 범위를 확인했어요

## 09. 기록하고, 혼자 한 번 더 실행해요

### 할 일

1. 새 작업에서 2주차 자료를 다시 읽히되 week-03.md로 저장합니다.

2. 내가 언제 무엇을 돌렸고 어떤 오류를 고쳤는지 남깁니다.

3. 아래 완료 기준을 말로 설명할 수 있으면 기본 실습이 끝납니다. 예약 실행은 추가 실습에서 직접 선택합니다.

### 입력 예시

```text

templates/request.txt로 input/week-02.txt를 정리해 output/week-03.md에 저장해줘.
실행일은 실제 확인 가능한 경우만 적고, input 이름·output 이름·확인한 항목·고친 내용·성공/실패를 output/run-log.md에 추가해줘.
기존 기록은 삭제하지 마. 예약이나 외부 발송은 하지 마.

```

### 정상 결과

서로 다른 이름의 보고서 3개와 실행 기록이 있습니다. 입력 이름을 바꾸는 곳을 혼자 찾을 수 있습니다.

### 막혔을 때

실패도 기록입니다. 실패 원인과 다음 행동을 적고 원인 하나만 고친 뒤 새 이름으로 다시 실행하세요.

- [ ] 새 작업에서 보고서를 재실행하고 기록했어요

## 추가 실습 · 스킬과 예약 실행

스킬: Codex에 아래 요청을 보내 지침만 있는 스킬을 만듭니다. 생성 파일의 이름과 설명·입력·출력 규칙을 직접 읽습니다. 새 작업에서 해당 스킬을 지정해 input/week-02.txt → output/skill-report.md를 실행하고 기대 결과와 비교합니다.

예약: 기본 실습이 성공한 사람만 공식 예약 작업 안내를 엽니다. 현재 앱의 예약 작업 생성 기능에서 연습 폴더·시각·시간대·처리 범위·결과 확인 방법을 정합니다. 로컬 실행에 필요한 앱 실행 상태와 컴퓨터 조건은 현재 공식 안내에서 확인하세요. 로컬 파일 예약은 컴퓨터가 켜져 있고 앱이 실행 중이어야 합니다.

아래 예약 초안을 먼저 읽고 실제 시각을 정합니다. 생성 화면에 보이는 일정과 Asia/Seoul 시간대를 확인한 뒤 생성하세요. 자동화 기능이 계정에 없으면 만들었다고 체크하지 말고 수동 실행까지 완료로 기록합니다.

한 번 실행된 기록과 output 파일을 확인한 뒤 예약 목록에서 해당 작업을 일시정지합니다. “예약됨”은 성공이 아닙니다. 결과가 없으면 실행 기록의 오류를 먼저 확인하세요.

```text

스킬 연습 요청:
이 연습 폴더의 .agents/skills/meeting-report/SKILL.md를 만들어줘.
name은 meeting-report, description은 주간 모임 메모를 보고서로 정리할 때 사용하는 절차라고 적어줘.
templates/request.txt의 입력·출력 규칙을 포함하고 실행 스크립트는 추가하지 마.
사용자 전체 스킬 폴더는 바꾸지 마. 새 작업에서 이 스킬로 보고서를 만드는 방법을 알려줘.

예약 초안 (아직 생성하지 말고 검토):
매일 [내가 정한 시각], Asia/Seoul, 현재 연습 폴더에서 input/week-02.txt를 templates/report-template.md로 정리.
output에 매번 겹치지 않는 파일 이름으로 저장, 실제 실행 기록 남기기.
입력 보존, 없는 정보는 미정, 외부 발송 없음.
한 번 결과 확인 후 내가 일시정지할 예정. 실제 생성 전 시각·대상 폴더·실행 조건을 보여줘.

```

스킬로 만든 보고서가 같은 기준을 통과합니다. 예약은 실제 실행 기록과 새 결과 파일을 확인해야 성공이며, 확인 후 일시정지 상태가 보여야 합니다.

## 혼자 해보기 확인

- 입력 파일만 바꿔 보고서를 만들 수 있나요?

- 준호의 완료 개수와 미정 담당자를 근거로 설명하나요?

- 요청문 저장과 예약 실행이 다르다는 것을 설명하나요?

## 진행자 메모
