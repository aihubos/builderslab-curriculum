# 새로고침해도 남는 나의 할 일 앱

입력·완료·삭제와 브라우저 저장을 만들고, 빈 입력·긴 글·중복 항목까지 직접 확인합니다.

## 먼저 확인

01·05 완료. 홈페이지가 내용을 보여줬다면 앱은 입력에 따라 목록이 변합니다. 인터넷 공개나 계정 로그인은 만들지 않습니다.

## 준비

ZIP 압축을 풀고 START-HERE.txt가 보이는 폴더를 작업 폴더로 엽니다. AI 작업은 본인 앱에서 실행합니다.

## 01. 실습 꾸러미와 작업 폴더 준비

### 할 일

1. 위의 실습 꾸러미 ZIP을 내려받습니다. ZIP은 여러 파일을 담은 포장 상자입니다. 압축을 풀어야 파일을 바꿀 수 있어요.

2. 문서에 practice-과정이름 폴더를 만들고 압축을 푼 파일들을 넣습니다. START-HERE.txt가 바로 보이는 위치를 찾으세요.

3. Codex에서 그 폴더를 프로젝트로 열고 새 작업을 만듭니다. 01 과정의 폴더 열기 단계가 낯설면 먼저 돌아가 연습하세요.

4. 아래 요청을 보내 파일 목록을 확인합니다. 이번에는 파일을 수정하지 않습니다.

### Windows

ZIP에서 마우스 오른쪽 버튼 → 모두 압축 풀기. 풀린 폴더를 문서로 복사하세요. 파일 탐색기에서 START-HERE.txt가 있는지 확인합니다. ZIP 안을 바로 열어 작업하지 마세요.

### Mac

Finder의 다운로드에서 ZIP을 두 번 누르면 폴더가 생깁니다. 그 폴더를 문서로 옮기세요. Finder에서 START-HERE.txt가 있는지 확인합니다.

### 입력 예시

```text

지금 열린 연습 폴더의 경로와 파일 목록만 알려줘. 아직 파일을 수정하지 마.
확인할 파일: tasks.txt, acceptance.txt, run-server.py

```

### 정상 결과

Codex가 알려준 경로가 내가 고른 폴더와 같고, tasks.txt, acceptance.txt, run-server.py가 보입니다.

### 막혔을 때

파일이 없으면 압축을 푼 바깥 폴더가 아니라 START-HERE.txt가 있는 폴더를 다시 여세요. 파일명 끝에 (1)이 있으면 실제 이름을 요청문에 적습니다.

- [ ] 연습 폴더와 입력 파일을 확인했어요

## 02. 화면과 데이터를 나눠 생각해요

### 할 일

1. tasks.txt의 세 할 일을 읽습니다.

2. 한 항목은 고유 번호(id), 글(title), 완료 여부(done)를 가진다는 것을 확인합니다.

3. 목록·입력·버튼을 화면, 배열에 저장된 항목들을 데이터라고 구분해보세요.

### 입력 예시

```text

tasks.txt와 acceptance.txt를 읽어줘.
할 일 앱의 입력→항목 추가→완료 표시→저장→다시 열기 흐름을 설명해줘.
항목 데이터는 id/title/done이고 같은 문장도 서로 다른 id를 가져야 해.
추가·완료·삭제만 먼저 만들고 로그인·서버 DB·동기화는 제외해줘. 아직 코드는 쓰지 마.

```

### 정상 결과

같은 문장 두 개도 서로 다른 항목이라는 설명이 있습니다. 화면이 보이는 것과 저장되는 것이 구분됩니다.

### 막혔을 때

메일 알림·회원가입을 제안하면 기본 기능 3개로 다시 줄입니다.

- [ ] 입력·화면·저장 데이터의 차이를 설명할 수 있어요

## 03. 기본 앱을 만들어달라고 해요

### 할 일

1. Codex에 아래 요청을 보냅니다.

2. 이번에는 index.html·style.css·app.js 세 파일로 만듭니다. 각 파일이 어디에 생겼는지 확인하세요.

### 입력 예시

```text

output에 index.html, style.css, app.js로 할 일 앱을 만들어줘. 외부 라이브러리는 사용하지 마.
처음은 빈 목록. 입력 1~120자, 공백만 있거나 120자를 넘으면 이유를 안내하고 추가하지 마.
추가 버튼과 Enter, 항목별 완료 체크와 삭제 확인/취소를 제공해줘.
각 항목에 고유 id를 주고 같은 문장도 별도로 처리해줘.
localStorage 키는 my-todo-practice-v1. 읽은 데이터의 형식 확인과 저장 실패 안내를 넣어줘.
손상된 저장 데이터는 자동으로 지우거나 덮어쓰지 말고 오류를 알린 뒤 읽기 전용 상태로 멈춰줘.
사용자 입력은 HTML로 해석하지 말고 문자로 표시해줘.
390px 한 열, 긴 문장 줄바꿈, label과 키보드 초점 표시. 기존 파일은 덮어쓰기 전에 알려줘.
온라인 공개나 계정 기능은 추가하지 마.

```

### 정상 결과

세 파일이 있고 입력·목록·완료·삭제 기능이 구현되어 있습니다. 아직 저장 성공을 단정하지 않습니다.

### 막혔을 때

화면만 만들었다면 “버튼을 눌렀을 때 데이터가 바뀌는 처리도 구현해줘”라고 요청하세요.

- [ ] 세 파일로 앱을 만들었어요

## 04. 같은 주소로 로컬 앱을 열어요

### 할 일

1. 브라우저 저장을 일정하게 확인하려면 file:로 열기보다 같은 localhost 주소를 사용합니다.

2. 꾸러미의 run-server.py는 이 연습 폴더만 내 컴퓨터에 보여주는 Python 기본 서버입니다. 설치된 Python 3가 있는지 Codex에게 먼저 확인하게 하세요.

3. Python이 없으면 공식 다운로드 안내를 보고 진행자와 설치한 뒤 계속합니다. 설치 명령을 모르면 복잡한 설정을 추측하지 마세요.

4. Codex가 서버를 계속 실행한 상태에서 http://127.0.0.1:8765/output/을 엽니다.

### Windows

직접 실행할 때: START-HERE.txt가 있는 폴더의 빈 곳에서 “터미널에서 열기”를 선택하고 py run-server.py를 입력합니다. py가 없다면 공식 Python 설치부터 진행자와 확인하세요.

### Mac

직접 실행할 때: 터미널에서 cd와 공백을 입력한 후 Finder의 연습 폴더를 창으로 끌어놓고 Return. 이어 python3 run-server.py를 실행합니다. 종료는 그 터미널에서 Ctrl+C입니다.

### 입력 예시

```text

이 연습 폴더에서 Python 3가 사용 가능한지만 먼저 확인해줘.
있으면 run-server.py를 실행해 내 컴퓨터의 127.0.0.1:8765에서 유지하고 http://127.0.0.1:8765/output/을 열어줘.
이미 포트를 쓰고 있으면 다른 프로세스를 종료하지 말고 알려줘. Python이 없으면 설치하지 말고 공식 설치 안내를 알려줘.
생성한 할 일 앱이 실제 표시되는지 확인해줘.

```

### 정상 결과

주소창이 http://127.0.0.1:8765/output/이고 내 앱 화면이 보입니다. 서버를 닫으면 새로 열 수 없으므로 실행 창을 유지합니다.

### 막혔을 때

Connection refused면 서버 실행 상태를 봅니다. 404면 output/index.html 경로를 확인합니다. 포트를 바꾸면 다른 저장 공간이므로 기존 할 일이 안 보일 수 있습니다.

- [ ] 고정된 로컬 주소에서 앱을 열었어요

## 05. 세 가지 할 일을 입력하고 완료해요

### 할 일

1. tasks.txt의 문장을 한 줄씩 입력합니다. 한 번은 버튼, 한 번은 Enter로 추가해봅니다.

2. 첫 항목에 완료 체크를 하고 다시 해제합니다.

3. 같은 문장을 한 번 더 추가해 두 항목이 서로 독립적인지 확인하세요.

### 입력 예시

```text

앱에서 직접 입력할 내용:
메모 한 개 정리하기
자료 출처 확인하기
오늘 배운 내용 남기기
메모 한 개 정리하기

첫 번째 “메모 한 개 정리하기”만 완료했다가 해제해보세요.

```

### 정상 결과

총 4개가 보입니다. 같은 문장 두 개 중 하나만 완료해도 다른 항목은 바뀌지 않습니다.

### 막혔을 때

같은 문장이 함께 바뀌면 문장을 고유 번호처럼 쓰고 있을 수 있습니다. “각 항목 id로만 찾아 수정해줘”라고 요청합니다.

- [ ] 추가·완료·해제·중복 항목을 확인했어요

## 06. 입력의 경계를 확인해요

### 할 일

1. 빈칸, 공백만, 긴 글, HTML처럼 보이는 글을 각각 넣습니다.

2. 120자를 넘기는 입력은 아래 문구를 충분히 반복해서 넣어보세요.

3. 오류 안내 후 정상 입력도 다시 가능한지 확인합니다.

### 입력 예시

```text

검사할 입력:
1. 아무 글자도 없이 추가
2. 공백 세 칸만 추가
3. 아래 문장을 6번 이어 붙여 120자를 넘긴 뒤 추가
긴 메모가 들어와도 화면 밖으로 나가지 않는지 확인하는 연습입니다.
4. <b>메모</b>

기대: 1~3은 안내하고 추가하지 않음. 4는 문자 그대로 추가.

```

### 정상 결과

잘못된 입력은 목록을 늘리지 않습니다. <b>메모</b>는 태그가 아닌 문자로 보입니다. 정상 입력을 다시 넣을 수 있습니다.

### 막혔을 때

빈 항목이 생기면 저장하기 전에 공백을 제거해 검사하도록 수정 요청합니다. 긴 글은 무작정 잘라 저장하지 말고 사용자가 줄이도록 안내합니다.

- [ ] 빈 입력·긴 입력·문자 표시를 확인했어요

## 07. 삭제를 취소하고, 한 개만 지워요

### 할 일

1. 중복 항목 하나의 삭제 버튼을 누르고 확인에서 취소합니다.

2. 다시 누르고 삭제를 확인합니다. 같은 문장의 다른 항목이 남는지 확인하세요.

### 입력 예시

```text

문제 재현 예시를 Codex에 보낼 때:
행동: 같은 문장 두 개 중 첫 항목 삭제 → 취소.
기대: 두 항목 모두 유지.
실제: [직접 관찰한 결과]
취소가 유지되는지, 확인하면 선택한 id 하나만 삭제되는지 고쳐줘.

```

### 정상 결과

취소는 목록을 바꾸지 않습니다. 확인하면 선택한 항목만 지워집니다.

### 막혔을 때

여러 개가 사라지면 중복 id가 있는지 확인합니다. 삭제를 숨기는 대신 데이터에서 해당 id만 제거해야 합니다.

- [ ] 삭제 취소와 한 항목 삭제를 확인했어요

## 08. 새로고침하고 다시 열어요

### 할 일

1. 항목 개수와 완료 상태를 메모합니다.

2. 브라우저 새로고침 후 같은지 확인합니다. 탭을 닫은 뒤 같은 브라우저·같은 주소로 다시 엽니다.

3. 다른 브라우저·다른 기기에는 옮겨지지 않는다는 것을 설명해보세요.

### 입력 예시

```text

확인 기록을 output/check-result.md에 적어줘. 내가 관찰한 값만 사용해.
새로고침 전 항목 수: [직접 입력]
새로고침 후 항목 수: [직접 입력]
완료 상태 유지: [직접 입력]
다시 연 주소: http://127.0.0.1:8765/output/
확인하지 않은 항목은 미확인으로 남겨줘.

```

### 정상 결과

항목 수와 완료 상태가 유지됩니다. 브라우저 데이터 삭제·비공개 창·주소 변경 시 달라질 수 있음을 이해합니다.

### 막혔을 때

기록이 사라지면 주소·포트·브라우저가 같은지 먼저 확인하세요. 저장이 차단되었거나 데이터가 손상되었다는 오류가 있으면 내용을 보존하고 원인을 확인합니다.

- [ ] 새로고침과 다시 열기 후 저장을 확인했어요

## 09. 불편 하나를 고치고 다시 점검해요

### 할 일

1. 앱이 작동하는 상태에서 output 폴더를 backup으로 복사합니다.

2. 남은 할 일 개수 표시 기능 한 가지를 추가합니다.

3. 완료/해제를 해 개수가 바뀌는지, 기존 목록이 유지되는지 확인합니다. 05 교재의 방법으로 390px와 Tab 이동도 검사하세요.

### 입력 예시

```text

현재 output 폴더를 backup/before-count에 복사해줘. 이미 있으면 새 백업 이름을 사용해줘.
미완료 항목 수를 보여주는 “남은 할 일 N개”만 추가해줘.
기존 저장 키와 데이터는 유지하고 완료·해제·삭제 때 숫자가 갱신되게 해줘.
빈 입력·중복 항목·새로고침·390px·Tab과 Enter를 확인하는 순서를 알려줘.

```

### 정상 결과

미완료 개수가 실제 목록과 같습니다. 기존 데이터와 다른 동작이 유지되며 작은 화면에서 버튼이 가려지지 않습니다.

### 막혔을 때

기능 추가 후 문제가 생기면 백업을 별도 폴더로 열어 비교합니다. 잘되던 파일을 먼저 지우지 마세요.

- [ ] 기능 하나를 추가하고 기존 동작도 다시 확인했어요

## 10. 혼자 다시 실행하고 사용법을 남겨요

### 할 일

1. 서버를 종료했다면 같은 명령으로 다시 시작합니다.

2. 동일 주소를 열고 항목 하나를 추가→완료→새로고침합니다.

3. 실제 관찰한 결과를 acceptance.txt와 대조하고 사용 방법을 작성합니다.

### 입력 예시

```text

HOW-TO.md에 이 앱의 시작 방법, 고정 주소, 추가·완료·삭제 방법, 저장 위치의 의미를 쉬운 말로 정리해줘.
같은 브라우저·같은 주소에서만 저장된다는 한계, 데이터 삭제 시 사라진다는 점, 서버 종료 방법도 적어줘.
acceptance.txt 각 항목에 내가 실제 확인한 결과만 기록하고 미확인은 미확인으로 남겨줘.
기존 데이터를 지우거나 앱을 배포하지 마.

```

### 정상 결과

앱을 다시 열고 사용할 수 있으며, 입력→처리→저장→결과의 흐름과 저장 한계를 설명합니다.

### 막혔을 때

완료 체크는 코드를 만들었다는 표시가 아닙니다. 직접 눌러보고 확인한 항목만 체크하세요.
