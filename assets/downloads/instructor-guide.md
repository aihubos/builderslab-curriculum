# AI 빌더스랩 실습 진행자 안내

설명 → 같이 한 번 → 직접 확인 → 다른 입력으로 혼자 반복하는 순서로 진행합니다.

설치나 파일 관리가 막힌 학생은 해당 단계에서 동행하며 미완료를 완료로 표시하지 않습니다.

01 첫걸음: 설치·폴더·첫 메모·원문 대조·두 번째 메모 반복. 이어서 아래 과정을 선택합니다.

## 두 주의 메모로 만드는 나의 업무 루틴

01에서 입력 파일을 읽고 결과 파일을 직접 확인해봤다면 시작할 수 있어요.

보고서 생성 전 학생이 입력 파일 이름을 소리 내어 읽게 합니다.

완료/예정을 섞은 결과를 실패가 아니라 교정 연습으로 사용합니다.

스킬·예약은 기본 보고서 두 개를 확인한 뒤 진행합니다.

완료 확인:

입력 파일만 바꿔 보고서를 만들 수 있나요?

준호의 완료 개수와 미정 담당자를 근거로 설명하나요?

요청문 저장과 예약 실행이 다르다는 것을 설명하나요?

## 원문으로 돌아갈 수 있는 나의 작은 위키

01 완료. Markdown은 처음이어도 됩니다. #은 제목, [이름](경로)은 파일로 가는 링크라는 것부터 연습해요.

S4는 충돌 연습 전까지 읽히지 않습니다.

Markdown 문법 암기보다 링크를 직접 따라가는 경험을 먼저 만듭니다.

이 교재의 운영 규칙은 가상 자료라고 수업 시작 때 알립니다.

완료 확인:

회비가 얼마인지 물었을 때 추측을 멈추나요?

S1과 S4의 차이와 현재 규칙의 근거를 설명하나요?

요약에서 원문으로 돌아갈 수 있나요?

## 내 컴퓨터에서 시작하는 메모 정리 비서

01·02 완료 권장. 개인 Windows 또는 Apple Silicon Mac, 인터넷, 본인 구독 계정을 준비하세요. 계정 연결이 확인되어야 AI 실습을 진행할 수 있어요.

기종과 기존 구독 연결을 실습 시작 전에 확인합니다. 인증은 학생이 직접 진행합니다.

설치·인증에서 막힌 학생은 완료 처리하지 않고 그 지점부터 동행합니다.

이 교재 작성 과정에서 수강생 Windows/Mac의 신규 설치와 인증까지 대행 검증한 것은 아닙니다. 공식 문서 확인일과 실제 화면 차이를 수업 전에 확인하세요.

완료 확인:

모델 응답과 실제 파일 저장을 각각 확인했나요?

새 대화에서 규칙 파일을 다시 지정하나요?

없는 파일을 지어내지 않고 멈췄나요?

## 소개 한 문장에서 시작하는 나의 홈페이지

01 완료. HTML은 브라우저가 읽는 문서이고, CSS는 색·여백을 정하는 규칙입니다. 직접 코드를 외우지 않아도 됩니다.

처음에는 이미지·회원가입·배포를 추가하지 않고 한 페이지 완성을 돕습니다.

개발자 도구는 함께 한 번 열어주고 학생이 두 번째 너비를 직접 바꾸게 합니다.

완성 예시는 HTML/CSS로 직접 만든 교육용 자료입니다. 외부 강의 영상과 구분합니다.

완료 확인:

버튼의 이동 대상을 말할 수 있나요?

새로고침 후 내가 바꾼 문구가 보이나요?

백업과 현재 파일을 구분하고 작은 화면을 확인했나요?

## 새로고침해도 남는 나의 할 일 앱

01·05 완료. 홈페이지가 내용을 보여줬다면 앱은 입력에 따라 목록이 변합니다. 인터넷 공개나 계정 로그인은 만들지 않습니다.

서버와 앱 화면을 별개로 설명하고 고정 주소를 적어둡니다.

첫 시연 때 정답 예제의 저장 데이터가 아니라 새 학생용 폴더를 사용합니다.

저장 실패·손상 데이터 대응은 진행자가 코드를 확인하고 기본 실습 후 별도 환경에서 보여줍니다. 학생의 기존 기록을 손상시키는 연습은 하지 않습니다.

완료 확인:

빈 입력과 같은 문장 두 개를 각각 확인했나요?

새로고침 후 항목과 완료 상태가 유지되나요?

다른 기기로 자동 동기화되지 않는다는 점을 설명하나요?
